# FoxCull audit — performance + correctness (2026-08-02)

Two independent read-only audits (perf/architecture, correctness/robustness) run
under the owner's "solve everything" mandate. This is the ranked backlog with
status. The scroll-freeze itself is tracked separately
(`FREEZE-INVESTIGATION-2026-08-02.md`); several findings below reinforce it.

## Landed in v1.4.0-nightly.3 (safe, contained, verified `npm run check` + `cargo check`)

- **C2 — video trim diagnostics + stream mapping** (`video.rs`): `trim` now
  captures stderr and returns the real ffmpeg error instead of a constant
  "ffmpeg trim failed", and uses `-map 0:v -map 0:a?` instead of `-map 0` so a
  data/timecode track (DJI/GoPro/phone MOV) can't fail the stream-copy cut.
- **C3 — concat temp-file collision** (`commands.rs`): the lossless-concat list
  file is now pid+sequence unique, so overlapping/rapid-restart exports can't
  clobber each other.
- **C6 — restore_trash duplicate on partial failure** (`commands.rs`): the
  cross-volume fallback deletes its copy if the source can't be removed, so a
  file is never left duplicated (and a retry can't create a 2nd restore).
- **P8 — per-tile sprite probes** (`Thumb.svelte`): the two `*_cached` IPC probes
  fired on every video tile and every recycle, bypassing the loader; now gated
  behind Live Scrub (unused on the default decoder path) and collapsed to the one
  dense probe. Reduces per-recycle churn while scrolling video folders.
- **P9 — warm payload** (`+page.svelte`): folder-open warming now sends only the
  first 600 image paths (its actual cap) instead of thousands of mostly-discarded
  paths over IPC.
- **P12 — dead code** (`+page.svelte`): removed the never-called `relatedScore`
  and corrected the stale comment claiming the stack index rebuilds on mark edits
  (it does not).

## Pending — ranked, need measurement and/or owner steer

### Top follow-ups (do next, with device measurement)

- **P2 — asset-protocol serving cost + uncapped off-heap image memory.**
  **2026-08-03 correction:** this did *not* corroborate the freeze RCA. Owner
  symptoms proved the JS main thread was blocked, and the loader's reactive-write
  storm + synchronous settle burst were fixed and stress-verified separately.
  `convertFileSrc` still bridges every tile fetch through WebView2's custom-scheme
  pipeline, and WebView2 still owns uncapped off-heap decoded-image memory, so this
  remains a measured optimization/ceiling question rather than a freeze fix.
  **Possible implementation:** a token-gated localhost
  `tiny_http` range server for the cache dir (reuse `cast.rs`), point `fileSrc` for
  cached thumbs/posters at it, add `Cache-Control`/`ETag`, cap concurrency; keep
  originals on the asset scope; add a CSP `img-src` entry. Instrument
  handle-count-per-fetch first so the cutover is measured, not assumed. Do NOT
  use data-URLs for tiles (pushes bytes into the JS heap).
- **P1 — O(N²) stack re-rooting** (`buildRelatedIndex`, `+page.svelte`): on a flat
  camera-dump folder (the common cull case) every singleton scans every root →
  ~36M string compares on a 6k folder, re-run on open/filter/sort/group/captures.
  Main-thread block on folder open. Fix: hash-set prefix lookup (O(N·L)) or skip
  the pass for flat-dump parents.
- **C1 — swallowed mark-write errors** (`+page.svelte` ~20 sites, `api.ts`
  `setVideoSegments`/`clearTrim`): mark mutations are optimistic + `.catch(()=>{})`,
  so a failed catalog write shows in the UI and enters the undo snapshot but is
  never persisted — the exact swallow class that hid the trim bug. Currently latent
  (args are correct), but any future arg rename regresses silently. Fix: surface
  failures via `activity.error` + revert/refetch, like the move/delete paths.

### Medium

- **P3 — Edit source pane not virtualized** (`EditStudio.svelte`): renders one
  `Thumb` per file for folders of thousands (the 8 GB case). Route it through the
  recycler with its own cell snippet.
- **P5 — redundant ffmpeg probes**: `capture_dates` spawns `ffmpeg -i` per video;
  opening one clip spawns up to 4 `ffmpeg -i` for the same metadata. Unify to one
  probe per clip, cached in the catalog like `captures`.
- **P4 — RAW thumbnail extraction reads whole file + brute-scans**
  (`thumbs.rs`/`media.rs`): use `raw.rs`'s IFD walk + a ranged read of the preview.
- **P6 — no cache eviction** (`precache-policy.md §9`): LRU/size-capped sweep;
  evict proxies/previews first.
- **P10 — SQLite single mutex + case-insensitive `LIKE` prefix scans**
  (`catalog.rs`): `LIKE 'prefix/%'` disables the index range; use a range predicate
  or `GLOB`; consider a read-only 2nd connection for folder-open queries.

### Lower

- **P7 — sort comparator allocates `Date`s + recomputes section keys per compare**
  (`+page.svelte`): decorate-sort-undecorate.
- **P11 — `includeSub` default-true does a full recursive HDD walk before first
  paint**: product default + optional streamed enumeration.
- **C4 — read/preview/cast commands accept arbitrary absolute paths** (unlike the
  guarded mutating commands): scope them for defense-in-depth.
- **C5 — folder-count badges stale after a delete sweep** (move invalidates
  counts, delete doesn't): clear `dir_counts` in `forget`/bump `countsGen`.

## Confirmed non-issues
- camelCase invoke args: all ~60 sites currently correct (verified).
- effect self-invalidation trap: `tilePending` etc. are plain `let` (guarded).
- move/delete rel-key drift, metadata orphaning, cast token traversal: clean.
